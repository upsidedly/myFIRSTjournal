## What is Pedro Pathing?

Pedro Pathing is a path follower for FTC autonomous routines. It helps your robot move along planned paths instead of guessing with timed motor power.

If you are new to it, do not try to learn every feature at once. Start with a single straight path, then add heading control, then curves, and only after that move into callbacks and custom tuning.

## Prerequisites

Before you use Pedro Pathing, you should have:

- An omnidirectional drivetrain, such as mecanum, x-drive, or swerve.
- A localization method. Dead wheels, the goBILDA Pinpoint, SparkFun OTOS, or drive encoders all work.
- Android Studio. The current docs do not target OnBot Java or Blocks.

## Why use it?

Pedro Pathing is a good fit when you want:

- Smoother autonomous motion than simple encoder-based driving.
- Easier tuning than many older path followers.
- Support for curved paths, headings, callbacks, and custom localizers.

## Start Here

If this is your first time using Pedro Pathing, read the page in this order:

1. Install the Quickstart.
2. Create the follower with your `Constants` file.
3. Drive one straight line before touching curves or callbacks.
4. Tune only enough to make that first path work.
5. Come back for the advanced sections later.

## Installation

### Quickstart

The easiest path is the Pedro Pathing Quickstart:

1. In Android Studio, choose `Main Menu -> File -> New -> Project from Version Control` and enter `https://github.com/Pedro-Pathing/Quickstart.git`.
2. Or clone it directly with `git clone https://github.com/Pedro-Pathing/Quickstart.git`.

### Manual setup

If you are not using the Quickstart, the current docs use these dependencies:

```groovy
repositories {
    google()
    mavenCentral()
    maven { url "https://mymaven.bylazar.com/releases" }
}

dependencies {
    implementation 'com.pedropathing:ftc:2.1.2'
    implementation 'com.pedropathing:telemetry:1.0.0'
    implementation 'com.bylazar:fullpanels:1.0.12'
}
```

Then sync Gradle, set the Compile SDK Version to `34` for both `FtcRobotController` and `TeamCode`, and copy the `pedroPathing` package from the Quickstart into your project.

## Choosing a dashboard

Pedro Pathing works with either Panels or FTC Dashboard.

Panels is the default recommendation in the Quickstart. It supports live tuning, field visualization, and logging, and it is available at `192.168.43.1:8001` when connected to robot Wi-Fi.

FTC Dashboard is still useful for visualization and logging, but it does not support live tuning of Pedro Pathing constants in the same way Panels does.

If you switch dashboards, make sure the drawing and telemetry code matches that dashboard's APIs.

## Constants and follower setup

The current docs keep robot configuration in a `Constants` file. Think of it as the place where you tell Pedro Pathing what robot you have and how hard it should correct itself.

That file usually contains:

- `FollowerConstants` for PIDF and tuning values.
- Drivetrain constants for your motor names and directions.
- Localizer constants for your odometry or sensor setup.
- `PathConstraints` for path completion and braking behavior.
- A `createFollower` method that builds the `Follower` for your OpMode.

If you only want to get moving quickly, you can treat the full constants file below as a reference template and fill in your own hardware names later.

### Java

```java
package org.firstinspires.ftc.teamcode.pedroPathing;

import com.qualcomm.robotcore.hardware.DcMotorSimple;
import com.qualcomm.robotcore.hardware.HardwareMap;

public class Constants {
    public static FollowerConstants followerConstants = new FollowerConstants()
            .mass(16.2)
            .forwardZeroPowerAcceleration(-25.93469313136796)
            .lateralZeroPowerAcceleration(-67.34249184408006)
            .translationalPIDFCoefficients(new PIDFCoefficients(0.03, 0, 0, 0.015))
            .translationalPIDFSwitch(4)

            .headingPIDFCoefficients(new PIDFCoefficients(0.8, 0, 0, 0.01))
            .secondaryHeadingPIDFCoefficients(new PIDFCoefficients(2.5, 0, 0.1, 0.0005))
            .drivePIDFCoefficients(new FilteredPIDFCoefficients(0.1, 0, 0.00035, 0.6, 0.015))
            .secondaryDrivePIDFCoefficients(new FilteredPIDFCoefficients(0.02, 0, 0.000005, 0.6, 0.01))
            .drivePIDFSwitch(15)
            .centripetalScaling(0.0005);

    public static MecanumConstants driveConstants = new MecanumConstants()
            .leftFrontMotorName("motor_lf")
            .leftRearMotorName("motor_lb")
            .rightFrontMotorName("motor_rf")
            .rightRearMotorName("motor_rb")
            .leftFrontMotorDirection(DcMotorSimple.Direction.REVERSE)
            .leftRearMotorDirection(DcMotorSimple.Direction.REVERSE)
            .rightFrontMotorDirection(DcMotorSimple.Direction.FORWARD)
            .rightRearMotorDirection(DcMotorSimple.Direction.FORWARD)
            .xVelocity(78.26192675242105)
            .yVelocity(61.494551922189565);

    public static PinpointConstants localizerConstants = new PinpointConstants()
            .forwardPodY(0.75)
            .strafePodX(-6.6)
            .forwardEncoderDirection(GoBildaPinpointDriver.EncoderDirection.FORWARD)
            .strafeEncoderDirection(GoBildaPinpointDriver.EncoderDirection.REVERSED);

    public static PathConstraints pathConstraints = new PathConstraints(
            0.995,
            0.1,
            0.1,
            0.009,
            50,
            1.25,
            10,
            1
    );

    public static Follower createFollower(HardwareMap hardwareMap) {
        return new FollowerBuilder(followerConstants, hardwareMap)
                .mecanumDrivetrain(driveConstants)
                .pinpointLocalizer(localizerConstants)
                .pathConstraints(pathConstraints)
                .build();
    }
}
```

## Tuning

The 2026 docs organize tuning into these steps. You do not need to finish all of them before your robot moves for the first time.

1. Setup constants.
2. Swerve setup, if you are using swerve.
3. Localization.
4. Velocity tuners.
5. Heading tuner.
6. Either predictive braking or the PIDF-based drive algorithm path.

If you use the PIDF path, you will also tune zero power acceleration, translational and drive PIDFs, and centripetal force. For beginners, the main goal is not perfection, just a path that finishes reliably and drives in the right direction.

## Path building

`PathBuilder` is the part beginners should focus on after installation. It is how you tell Pedro Pathing where to go.

The important idea is simple: a `PathChain` is a route made of one or more paths, and the follower walks through it from start to finish.

### Simple straight path

Start with this example. If this does not work, do not move on to curves or callbacks yet.

<Tabs items={['Java', 'Kotlin']}>
<Tab value="Java">

```java
PathChain path = follower.pathBuilder()
        .addPath(new BezierLine(new Pose(0, 0, 0), new Pose(40, 0, 0)))
        .setLinearHeadingInterpolation(0, 0)
        .build();

follower.followPath(path);
while (opModeIsActive() && follower.isBusy()) {
    follower.update();
}
```

Once you have one line working, this is the next beginner step: move in a line and turn at the same time.

### Callbacks and pausing

Callbacks let you run actions while the path is being followed. This is useful for grabbing game pieces or moving an arm without stopping the whole auto.

<Tabs items={['Java', 'Kotlin']}>
<Tab value="Java">

```java
PathChain scored = follower.pathBuilder()
        .addPath(new BezierLine(new Pose(0, 0, 0), new Pose(30, 0, 0)))
        .addParametricCallback(0.5, () -> claw.setPosition(1.0))
        .setLinearHeadingInterpolation(0, 0)
        .build();

follower.followPath(scored);
while (opModeIsActive() && follower.isBusy()) {
    follower.update();

    if (gamepad1.a) {
        follower.pausePathFollowing();
    }
    if (gamepad1.b) {
        follower.resumePathFollowing();
    }
}
```

</Tab>
<Tab value="Kotlin">

```kotlin
val scored = follower.pathBuilder()
```

### Detecting completion

The usual completion check is `!follower.isBusy()`. If you need to start the next action a little earlier, the current docs also mention `follower.atParametricEnd()` with a heading or velocity check.

## Advanced topics

### Speed control

Skip this until your first path is stable. The docs do not use a built-in speed limiter, so motor power and path constraints do most of the work.

### Optimization

Once the robot is already following paths correctly, Pedro Pathing suggests:

- Raising drive P carefully if you need more speed.
- Using `.setGlobalDeceleration(double brakingStrength)` on a `PathChain`.
- Testing shorter paths first and then refining heading interpolation.

### Custom extensions

Only worry about these if you need something the built-in robot and localizer options do not cover:

- `CustomCurve` for your own curve types.
- `Drivetrain` for custom drive logic.
- `Localizer` for custom localization hardware.

If you are extending one of these, keep hardware in the subsystem class and put tunable values in a separate constants class.

## Example autonomous

This is a compact current-style autonomous example using the modern packages and `Constants.createFollower`. It is intentionally small so beginners can see the minimum they need before adding more behavior.

<Tabs items={['Java', 'Kotlin']}>
<Tab value="Java">

```java
import com.pedropathing.follower.Follower;
import com.pedropathing.geometry.BezierLine;
import com.pedropathing.geometry.Pose;
import com.pedropathing.paths.PathChain;
import com.qualcomm.robotcore.eventloop.opmode.Autonomous;
import com.qualcomm.robotcore.eventloop.opmode.LinearOpMode;

@Autonomous(name = "Pedro Auto Example")
public class PedroAutoExample extends LinearOpMode {
    private Follower follower;
    private PathChain driveForward;

    @Override
    public void runOpMode() {
        follower = Constants.createFollower(hardwareMap);
        follower.setStartingPose(new Pose(0, 0, 0));

        driveForward = follower.pathBuilder()
                .addPath(new BezierLine(new Pose(0, 0, 0), new Pose(40, 0, 0)))
                .setLinearHeadingInterpolation(0, 0)
                .build();

        waitForStart();

        follower.followPath(driveForward);
        while (opModeIsActive() && follower.isBusy()) {
            follower.update();
        }
    }
}
```

</Tab>

## Example TeleOp

The current teleop example uses `startTeleopDrive()` and `setTeleOpDrive(...)` for manual control, then switches into path following when needed. You can ignore this until you want driver control plus path following in the same OpMode.

## AprilTag integration

Pedro Pathing now shows AprilTag usage as pseudocode and relocalization support. You can ignore this until your base pathing is solid; this is the kind of feature you add after the robot already follows paths reliably.
